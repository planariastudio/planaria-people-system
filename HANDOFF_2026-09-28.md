## CURRENT STATE

The Worker can file to GoodDay instead of ClickUp. The code is **deployed** on `main`, and the
switch defaults **off**, so every task operation still goes to ClickUp.

Fully migrating is gated on **GoodDay invites**, not on code. Ten roster editors have no GoodDay
account; `goodDayResolveUserId` matches by name and returns null for them, so their tasks would be
created unassigned and nobody is told to fill anything in. That is the whole blocker.

### The switch

One secret, `GOODDAY_ENABLED`. The test is exact:

```
String((env && env.GOODDAY_ENABLED) || "") === "1"
```

- Not `"1"` (unset, `"0"`, empty): every task operation goes to ClickUp, unchanged.
- `"1"`: they all go to GoodDay. Same call sites, different destination.
- Unsetting it rolls back with no redeploy. That is why it is a flag.

**Open ambiguity as of 2026-09-28.** The secret `GOODDAY_ENABLED` exists in `wrangler secret list`,
but the list shows names, not values, so its value is unconfirmed. It must be off, because the three
secrets GoodDay needs to work (`GOODDAY_BOT_USER_ID`, `GOODDAY_TEAM_ID`, `GOODDAY_PEOPLE_ID`) are all
absent, so a value of `"1"` would mean a half-live, broken migration. Make it certain with
`npx wrangler secret put GOODDAY_ENABLED` and enter `0`.

### Migration, remaining steps

An interactive version of this lives at `goodday_migration_runbook.html` (checkbox state saved
per device). Legend: [you] needs your login, [me] the assistant does it, [wait] waiting on people.

Phase 1, prove the flag-off state is clean. DONE 2026-09-28. Secret audit above, whoami confirmed.

Phase 2, get people into GoodDay.
1. [you] Invite all 10 editors plus supervisors to GoodDay. The assistant cannot; standing rule.
2. [wait] Wait for invites to be accepted. Hard gate.
3. [you] Run `npm run provision`. One project per person under People > Performance Records.
   Dry-run by default, re-reads to prove no duplicates.

Phase 3, set GoodDay secrets and smoke test.
4. [you] Set `GOODDAY_TOKEN` (already set), `GOODDAY_BOT_USER_ID`, `GOODDAY_TEAM_ID`,
   `GOODDAY_PEOPLE_ID` as secrets via `wrangler secret put`. Never paste tokens into chat.
5. [you] Run `npm run smoke` against one real person. A 200 from GoodDay proves nothing; smoke
   reads back what actually stored (PDF on task, assignment, status).

Phase 4, flip.
6. [you] `npx wrangler secret put GOODDAY_ENABLED`, enter `1`.
7. [you] File one real case end to end, confirm the assignee is notified.
8. Rollback if wrong: unset `GOODDAY_ENABLED`, no redeploy.

Phase 5, finish.
9. [you] Rotate `PEER_ADMIN_KEY`; the old value is public.
10. [me, blocked] Rewrite both guide sites for GoodDay wording. Blocked here: the guide repos are
    not in the cloud container, only on Joshua's machine. Needs a local session or the repos pushed
    somewhere reachable.

### The one behaviour change to warn people about

A GoodDay task's description is its first message, and no API can edit it. Filing used to overwrite
the ClickUp task body with the result; now the result is appended below the original prompt, so a
task reads as a history rather than a final state. Both guide sites still describe the ClickUp
overwrite.

## Deploy

To ship the Worker: `npm run deploy` (runs the syntax gate and all tests via `predeploy`, then
uploads). Before any deploy, confirm every `env.X` the Worker reads is a secret or declared in
`[vars]`; `wrangler secret list` is the authority, not the comments. Secrets survive a deploy;
plaintext `[vars]` are replaced by whatever `wrangler.toml` declares. That is how the two
2026-09-19 outages happened.

Forms deploy by pushing to this repo (GitHub Pages). `kpi_card.js` and `peer_card.js` are
load-bearing shared modules. Apps Script (`config_editor_Code.gs`, `sheet_mirror_v2_Code.gs`)
deploys separately inside the Google Sheet; re-paste and re-deploy there when either changes.
